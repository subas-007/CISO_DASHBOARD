# Security Architecture & Control Mapping

## 1. Threat model summary

| Asset | Threats | Primary controls |
|-------|---------|------------------|
| Connector credentials (API keys, OAuth secrets, client keys) | DB theft, insider read, log leakage | AES-256-GCM with AAD, write-only API, log redaction, audit sanitisation |
| Executive risk data & justifications | Unauthorised read, tampering | OIDC + RBAC, field encryption, transactional audit |
| Audit trail | Repudiation, tampering, deletion | Append-only triggers, revoked privileges, HMAC hash chain |
| Sessions | Theft, fixation, CSRF, XSS exfiltration | `__Host-` httpOnly SameSite=Strict cookies, rotation + reuse detection, strict CSP |
| Internal network | SSRF via connectors, lateral movement | Egress policy with connect-time IP checks, network zones, mTLS |

## 2. OWASP Top 10 (2021) mitigation

| # | Risk | Mitigations in this codebase |
|---|------|------------------------------|
| A01 | Broken Access Control | Deny-by-default `authenticate` on all `/api`; per-route `requirePermission` ([rbac.ts](../backend/src/auth/rbac.ts)); SoD for risk approval; server-side session validation per request; denials audited |
| A02 | Cryptographic Failures | TLS 1.3 only (gateway, API, Keycloak, PostgreSQL); HSTS preload; AES-256-GCM field encryption with key ring; HMAC blind indexes; refresh tokens stored as SHA-256 only |
| A03 | Injection | Prisma parameterised queries (raw SQL only via tagged templates); Zod `.strict()` validation; no shell execution; XML entity expansion disabled; CSV-formula neutralisation in exports; React output encoding, no `dangerouslySetInnerHTML` |
| A04 | Insecure Design | Threat-modelled flows (see [FLOWCHARTS.md](FLOWCHARTS.md)); fail-closed audit; segregation of duties; zero data retention for third-party payloads |
| A05 | Security Misconfiguration | Startup refuses insecure prod settings; strict CSP / XFO / nosniff / Referrer-Policy / COOP / CORP; no stack traces in responses; non-root, read-only containers with `cap_drop: ALL` |
| A06 | Vulnerable Components | Pinned major versions with lockfiles; `npm ci --ignore-scripts`; minimal Alpine images with `apk upgrade`; npm removed from runtime image |
| A07 | Identification & Authentication Failures | OIDC + PKCE + nonce; IdP MFA (TOTP forced), password policy, brute-force lockout; 10-min access tokens; 15-min idle / 8-h absolute session; continuous IdP re-verification on refresh |
| A08 | Software & Data Integrity Failures | Audit hash chain; signed/encrypted tokens (HS512 JWT, JWE state); lifecycle scripts disabled during install |
| A09 | Security Logging & Monitoring Failures | Immutable audit for auth, admin, config, risk, access-denied events; JSON structured logs with redaction; KRI breach register; Keycloak login/admin events enabled |
| A10 | SSRF | Connector URL policy (https only, allowlist, denied hosts, no userinfo), connect-time DNS/IP verification (anti-rebinding), metadata/loopback/link-local/internal CIDRs blocked, redirects not followed, response size caps |

## 4. Cryptography

| Purpose | Algorithm | Key source |
|---------|-----------|-----------|
| Field encryption (credentials, emails, incident descriptions, acceptance justifications, IdP tokens) | AES-256-GCM, 96-bit random IV, AAD bound to record id | `DATA_ENCRYPTION_KEYS` (key ring) |
| Searchable encrypted fields | HMAC-SHA256 blind index | `BLIND_INDEX_KEY` |
| Access tokens | JWT HS512, 10 min | `JWT_SECRET` (≥ 64 chars) |
| OIDC state cookie | JWE `dir` + A256GCM | `STATE_ENCRYPTION_KEY` |
| Audit chain | HMAC-SHA256 | `AUDIT_HMAC_KEY` |
| Transport | TLS 1.3 (`TLS_AES_256_GCM_SHA384`, `TLS_CHACHA20_POLY1305_SHA256`, `TLS_AES_128_GCM_SHA256`), X25519/P-384 | `certs/` (replace with enterprise PKI) |

### Full-database encryption at rest

Application-level AES-256-GCM protects the sensitive fields above. For **all** database records
(including indexes, WAL and temp files), place the PostgreSQL volume on an encrypted block device:

```bash
# Ubuntu / RHEL — LUKS2 with AES-256 (aes-xts-plain64, 512-bit key)
cryptsetup luksFormat --type luks2 --cipher aes-xts-plain64 --key-size 512 /dev/sdX
cryptsetup open /dev/sdX pgdata && mkfs.xfs /dev/mapper/pgdata
mount /dev/mapper/pgdata /var/lib/docker/volumes   # or bind the pgdata volume here
```

Backups (`pg_dump`) must be encrypted too (e.g. `age`, `gpg --cipher-algo AES256`, or encrypted object storage).

### Key rotation (no downtime)

1. Append a new key: `v1:<old>,v2:<new>` in `secrets/data_encryption_keys`.
2. Set `DATA_ENCRYPTION_ACTIVE_KEY=v2` and restart the API. New writes use `v2`; existing `v1` ciphertexts still decrypt.
3. Re-save credentials (Integrations → Rotate credentials) to re-encrypt with `v2`. `needsReencryption()` in [crypto.ts](../backend/src/lib/crypto.ts) identifies stale ciphertexts for a batch job.
4. Remove `v1` only when nothing references it.

**Never rotate `AUDIT_HMAC_KEY` in place** — historic records would fail verification. Archive the old key with the exported log, or start a new chain segment.

## 5. Secrets management

* No secrets in source control: `.env`, `secrets/`, `certs/` are git-ignored; `.env.example` contains placeholders only.
* `scripts/generate-secrets.sh` creates every secret from a CSPRNG (`openssl rand`), mode `600`.
* The API receives secrets as **files** (`*_FILE`, Docker secrets) — not environment values visible in `docker inspect` — and scrubs them from `process.env` after loading.
* Vault pattern: set `SECRETS_PROVIDER=vault`, `VAULT_ADDR`, `VAULT_KV_MOUNT`, `VAULT_KV_PATH` and `VAULT_TOKEN_FILE` or `VAULT_ROLE_ID` + `VAULT_SECRET_ID_FILE` (AppRole). Keys in the KV secret use the same names (`JWT_SECRET`, `DATA_ENCRYPTION_KEYS`, …).

## 6. Zero data retention (third-party payloads)

* Raw connector responses exist only as an in-memory buffer that is **zero-filled** immediately after parsing.
* Only normalised fields are persisted; raw bodies are never logged (pino redaction of `*.body`, `*.payload`, `*.raw`, credentials) and upstream error bodies are never echoed.
* Data minimisation: threat intel and KPI snapshots are purged after configurable retention (`threatRetentionDays`, `snapshotRetentionDays`).

## 7. Production hardening checklist

- [ ] Replace `certs/` with enterprise-PKI certificates; move `ca.key` offline.
- [ ] Point `OIDC_*` at the corporate IdP (Entra ID / Okta / Ping) **or** remove demo users from `infra/keycloak/realm-ciso.json`; map IdP groups via `OIDC_ROLE_MAPPING`.
- [ ] Set `SEED_DEMO_DATA=false`.
- [ ] Encrypt the PostgreSQL volume (LUKS2) and backups.
- [ ] Configure `CONNECTOR_ALLOWED_HOSTS` to the exact tool endpoints; consider `CONNECTOR_BLOCK_PRIVATE_NETWORKS=true` if all tools are SaaS.
- [ ] Host firewall: allow only 443 (and 80 for redirect) inbound — `ufw allow 443/tcp` / `firewall-cmd --add-service=https --permanent`.
- [ ] Keep SELinux enforcing on RHEL (compose mounts use `:z` relabelling).
- [ ] Forward container logs and the audit CSV export to the SIEM; configure WORM retention.
- [ ] NTP/chrony on the host.
- [ ] Enable Docker content trust / image scanning (Trivy, Grype) in CI.
- [ ] Back up `secrets/data_encryption_keys` and `secrets/audit_hmac_key` to the vault — losing them makes data unreadable.
